# ConfusingURLBuilder

A 100% client-side URL-parsing-confusion payload generator (SSRF /
allowlist bypass). Unlike a static cheatsheet, every payload is checked
against a **real** parser/library (32 languages), and the `../` path
correction needed to reach exactly the desired path is computed
automatically instead of guessed by hand.

It also supports true differential mode: pick a **requester parser** (the
one that actually sends the HTTP request) and a separate **validator**
(either a naive string check, or another real parser standing in for the
security check) — the tool shows exactly which techniques make the two
disagree.

## Run it

```sh
python3 -m http.server 8000
# then open http://localhost:8000
```

(Loading `data/*.json` via `fetch()` is blocked by the browser under
`file://` — the folder needs to be served over http.)

## Architecture

```
data/
  techniques.json         <- catalogue of technique templates (placeholders {S}{A}{AP}{T}{TP}{P}{C})
  technique-matrix.json   <- for every (technique, real parser) pair, the resolved host/path at
                              every correction level 0..max, plus the smallest level that reaches
                              the target with the exact desired path
js/
  templater.js             <- placeholder substitution
  validators.js             <- naive "validator" string checks (contains/startsWith/regex)
  ipEncode.js                <- alternate IPv4 encodings (decimal/octal/hex/IPv6-mapped)
  app.js                      <- UI, including requester-vs-validator differential logic
index.html, css/style.css
```

`technique-matrix.json` is generated by verifying each technique against
real parser/library implementations, not simulated or guessed. It's updated
here whenever new payload techniques or new parsers/libraries are added.

## How differential mode works

`technique-matrix.json` stores, per (technique, parser), the resolved
host/path at *every* correction level (not just the winning one). For a
chosen requester parser, the client picks the smallest level that makes the
requester land exactly on the target host + desired path. It then looks up
what the chosen validator (a different real parser, or a naive string
check) resolves *at that same level* — if the validator lands on the
allowed host while the requester lands on the target, that's a confirmed
bypass. Picking the same real parser for both roles always shows no
bypass, by construction: confusion only exists when the two disagree.

## Known limitations

- The matrix is derived using a canonical host/path, without a port.
  Combinations with a port or with alternate IP encoding are best-effort
  (structurally should still hold, but not empirically re-verified).
- Reflects the parser/library versions pinned at generation time.
- Generator only: no automated bulk request sending (no built-in scanner),
  so it stays usable under rate-limiting during an authorized engagement.
